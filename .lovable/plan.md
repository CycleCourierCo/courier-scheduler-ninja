## Switch Supabase URL to custom domain `api.cyclecourierco.com`

Now that the Supabase custom domain is configured, update the app to use it everywhere so all API calls and signed storage URLs (labels, invoices, etc.) come out on `https://api.cyclecourierco.com`.

### Changes

1. **`.env`** — update `VITE_SUPABASE_URL`:
   - from `https://axigtrmaxhetyfzjjdve.supabase.co`
   - to `https://api.cyclecourierco.com`

2. **`src/integrations/supabase/client.ts`** — update the hardcoded `SUPABASE_URL` constant to `https://api.cyclecourierco.com`.

3. **Codebase sweep** — search for any other hardcoded references to `axigtrmaxhetyfzjjdve.supabase.co` (there may be a few in edge functions, docs, or utility files) and swap them to the custom domain where they're used for public URLs. Server-side `SUPABASE_URL` inside edge functions is auto-injected by Supabase and does not need editing.

### Result

- All new Supabase requests from the browser go to `api.cyclecourierco.com`.
- New signed URLs generated by `createSignedUrl` (labels, invoices) will be issued on `api.cyclecourierco.com/storage/v1/object/sign/...` — matching the example URL you posted.
- Previously generated signed URLs still work on the old host until they expire; nothing to migrate.

### Notes

- `VITE_SUPABASE_PROJECT_ID` and the anon key stay unchanged.
- No database or edge function changes required.
- After deploy, if any request fails with CORS/SSL, it means the Supabase custom domain hasn't fully finished SSL provisioning yet — wait and retry.
