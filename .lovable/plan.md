# Shipday Webhook Security Finding — Verification and Fix

## What the check actually found

The finding says token validation is hardcoded off. That is no longer true in the current code: the webhook rejects any request whose `token` / `x-webhook-token` header does not match the `SHIPDAY_WEBHOOK_TOKEN` secret, and returns 401 otherwise.

However, a real problem exists: **`SHIPDAY_WEBHOOK_TOKEN` is not configured on this project** (nor is `SHIPDAY_API_KEY`). With no secret set, the webhook returns "Webhook not configured" (500) for every incoming call — so spoofing is blocked, but genuine Shipday events (driver assigned, collected, delivered) are being rejected too.

There is also a smaller issue: the function logs the complete set of incoming request headers, which writes the webhook token itself into the logs.

## What will be done

1. Remove the full-header log line and replace it with a safe, non-sensitive log (method plus event type only).
2. Ask you to create one strong random value, paste it into the Shipday webhook settings as the webhook token, and save the same value here as `SHIPDAY_WEBHOOK_TOKEN` through the secure secret form. Until that is saved, Shipday status updates cannot flow in.
3. Confirm whether `SHIPDAY_API_KEY` should also be added — the webhook uses it to double-check completion events, and it is currently missing.
4. Mark the security finding as fixed once the token check plus the configured secret are both in place.

Optional cleanup, if you want it in the same pass: the `TWOCHAT_API_KEY` and `TWOCHAT_FROM_NUMBER` secrets are now unused after the WhatsApp provider consolidation and can be deleted.

## Technical detail

- File: `supabase/functions/shipday-webhook/index.ts`. Validation already lives at the top of the handler ahead of any payload parsing or database write; no logic change is needed there.
- The `verify_jwt = false` entry in `supabase/config.toml` stays — Shipday cannot send a Supabase JWT, so the shared token is the correct authentication mechanism for this endpoint.
- The token must be generated by you rather than auto-generated here, because Shipday's dashboard needs the same literal value.
