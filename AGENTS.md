# Project architecture

- Thermal-label QR codes use a stable public tracking URL, print at the bottom-right of the label with a four-module quiet zone, and take the largest whole number of 203-dpi dots (three to five) that still fits; future signed-in destinations should be resolved at the destination so existing labels remain usable.

- Below laptop width the inbox shows either tickets or the route-selected conversation, with details in a sheet and collapsible ticket controls; its height is measured below the site header so only message history scrolls and the reply box remains visible.

- Public inspection decisions go through the `public-inspection-approval` Edge Function; privileged database approval helpers remain service-role-only to prevent direct browser execution.
- Warehouse bike-storage anniversaries are calculated in Europe/London and billed through the weekly QuickBooks invoice path with a service-role-only bike-month ledger, so missed months can be caught up without duplicate charges.
- Unboxed-bike preparation emails are sent from the order-creation background workflow to the collection contact and use an atomic order timestamp claim to prevent duplicates.
- Order-to-invoice associations use a dedicated many-to-many table; QuickBooks staff URLs are visible only to admin and customer-service roles.
- All collection labels share the renderer in labelUtils and preload original thermal artwork bytes before rendering; this preserves one-bit native-resolution images and consistent overflow protection across single, bulk and loading outputs.- Bookable product names come from one master list in the bike pricing constants; booking dropdowns, API and consistency report all read it so names cannot drift.
- Order cancellation time/user is stamped by a database trigger on orders.status; the cancelled-but-invoiced audit reads it with order_invoice_links, so every cancel path is covered.

- Bulk van loading goes through the load_orders_onto_van database function in one call — avoids per-bike saves and page reloads that lock the Loading page.
- Staff-visible pages must be added to the hardcoded ADMIN_MENU_SECTIONS list in Layout.tsx as well as the route/permissions config — the admin menu does not read the permissions matrix, so a page can be reachable yet absent from the menu.
- Order webhooks fan out to customer webhook configs and to partner apps (oauth_clients.webhook_url) the customer has an active OAuth grant with, deduped by URL — a sign-in connection alone must be enough for a partner to receive updates.
- Customer SMS goes through supabase/functions/_shared/divergentSms.ts (Divergent Connect), sent alongside WhatsApp and logged in sms_messages; delivery/replies arrive at divergent-webhook — one helper keeps sender, length limit and logging consistent.
- Tests run with vitest (`npx vitest run`), files named *.test.ts next to the code — one test per business rule.
- Colour comes only from the semantic tokens in src/index.css (status-*, segment-*, primary etc.); components never use raw palette utilities, and email hexes live once in _shared/emailLayout.ts mirrored by src/utils/emailBrand.ts — one source of colour keeps print, dark mode and email from drifting.
- Larger 48px controls are applied by Layout's FLOOR_SCREEN_PATHS (floor-controls class) and the doorstep-page shell, not per button — add new workshop/driver routes to that list.
- Customer-facing follow-ups after a browser action (e.g. availability confirmation emails, NI ferry booking) are sent by an Edge Function in the background, not chained in the browser — closing the page must not lose them.
- Admin-editable email settings live in email_templates and are applied inside send-email by template key (update.<stage> / type.<emailType>); a missing or broken template always falls back to the built-in email so customers never get a blank message.
- Van odometer = newest manual reading (vehicle_odometer_readings) plus approved timeslip miles dated after it, else purchase baseline plus all timeslip miles (src/lib/odometer.ts) — manual readings correct drift without rewriting timeslips.
- Fleet module: vehicles is the only van record; every change to vehicles, vehicle_issues, odometer readings and service logs/schedules is written to fleet_audit_log by the fleet_audit_trigger (read-only to admin/fleet_manager via is_fleet_staff) — history can't be silently edited from the app.
- Fleet inspections copy checklist items into fleet_inspection_results when started and lock once final (database trigger); corrections are new linked inspections, and defect rules (Red needs evidence + verifier to close) are enforced by a vehicle_issues trigger — so past records can't be rewritten and closure rules hold on every path.
- Fleet costs come only from fleet_repair_jobs plus vehicle_maintenance_logs without repair_job_id (src/lib/fleet/repairs.ts) — a repair that also rolls a service schedule forward is counted once. Finalising an inspection updates tyre tread, mileage and next_inspection_due in a database trigger so dashboard figures follow real inspections.
- Route-side van warnings come only from the fleet_vehicle_warnings security-definer function (planner roles see warning text, never defect records) via FleetVehicleWarnings; they never block or change the van, and red acknowledgements go to fleet_route_warning_acks. Fleet alert emails are queued by database triggers/cron to the fleet-alerts function (X-Cron-Secret) so every save path notifies.
- Radius Velocity tokens live only server-side (radius-positions function + service-role fleet_integration_tokens); the browser only receives trimmed positions for fleet staff — keeps telematics credentials and driver phone data out of the client.
- Each timeslip links to one saved route (timeslips.saved_route_id); a trigger freezes the plan into planned_snapshot, and planned-vs-completed reports read that snapshot so later edits to the saved route never rewrite history.
- Driver app = this web app wrapped by Capacitor (capacitor.config.ts); native-only APIs live in src/lib/driverApp/native.ts with browser fallbacks, so the website keeps working without the native shell.
- Drivers read their day only through the driver_today_stops security-definer function, keyed on saved_route_assignments.driver_id (not timeslips, which are filled in after the shift and only used for planned-vs-actual); stops stay hidden until driver_start_route stamps started_at. Proofs of delivery are queued on the phone first and uploaded to delivery_proofs/private storage, so poor signal never loses them.
- Saved routes are assigned to a van per date in saved_route_assignments; triggers copy the route onto that van's timeslip (before the planned-snapshot freeze), so van assignment is the single way a route reaches a driver.
- Stop ETAs (Radius position → remaining stops, +15 min per earlier stop) are computed only in eta-link using supabase/functions/_shared/stopEta.ts, which has no imports so Vitest tests the same rule.
- The Live Map's driven line is road-snapped by the snap-path function (Google Roads) and cached in service-role-only fleet_snapped_paths; deviation and mileage maths always use the raw tracker points, so snapping never changes what gets flagged.
- Label QR scans resolve by role at the destination: staff bike cards and scan actions go only through label_lookup / label_scan_action (security definer, role-checked) and every staff action is written to label_scans — printed labels never change and the chain of custody covers every scan path.
- Staff scan cards open only as a popup on staff pages (?scan=<ref>); signed-in staff opening a tracking link are redirected there, so the public tracking page never shows staff data.
- Label scan role tabs use the shared role-to-panel mapping and only expose assigned views; switching views never changes server permissions.
- Bay QR labels encode CCCBAY:<bay>[-<slot>] (parseBayCode in src/lib/labelScan.ts) and every scan-to-bay path saves through label_scan_action — bike and bay codes can never be confused and each allocation is logged.
- Service intervals resolve van override > fleet_service_interval_defaults > built-in DEFAULT_INTERVALS in computeNextDue; bulk servicing saves through fleet_bulk_log_service, and a mileage on any service record is also stored as an odometer reading — one rule for all vans, odometer stays in step.
- NI ferry-partner links carry orders.ni_partner_token (?k=); partner reads/writes check it and submit_ni_partner_details is service-role-only — the public tracking id must never authorise writes.
- Driver proofs of delivery reserve exact file paths in delivery_proof_uploads before insert-only uploads; the final proof must match that reservation, and unattributed phone-queue entries are quarantined — retries cannot replace evidence or upload under another login.
- Duplicate-safe writes claim first: customer Shopify lines insert their unique order-log row before booking, return-to-seller relies on one return per returned_from_order_id (unique index), and set_order_availability returns {error} for a wrong postcode instead of raising so failed attempts are kept.
- Sensitive columns are pinned by BEFORE UPDATE guard triggers (profiles pay/pricing, review_cycles parties, inspection_issues customer/mechanic limits) rather than column lists in RLS — every update path, including future ones, is covered.
- Edge functions that act for the business (webhook dispatch, credentialed proxies, unrestricted email) gate callers with _shared/staffAuth.ts identifyCaller (service role, X-Cron-Secret, or an explicitly allowlisted staff role); inbound webhooks fail closed when their secret is unset — one caller check keeps every path consistent.
- New public-schema functions must explicitly `REVOKE EXECUTE ... FROM PUBLIC, anon` in the same migration unless a signed-out website flow calls them; a 2026-10-28 sweep revoked anon/PUBLIC EXECUTE from all app functions (keep-list: availability, NI partner, public tracking/inspection/repair-offer, OAuth client lookup) and fully locked get_vault_secret to service_role — default PUBLIC grants otherwise leak internals.

- Fleet inspections save their expected checklist when started and can be finalised only after starting as a draft with every expected check present — the database derives the result and completion details so direct writes cannot skip checks.
- Inspection-report generation is limited to staff or the signed-in booking owner, while public decision endpoints refresh reports server-side; foam photo access uses a service-only, rate-limited receiver-postcode database check.
- Isle of Man reuses the Northern Ireland ferry flow: orders.is_northern_ireland means 'ferry order' and orders.ferry_region (northern_ireland|isle_of_man) picks partner, surcharge and wording via ferryPartnerFor/ferryRegionOf/localiseFerryText (client utils + _shared/northernIreland.ts) — one flow, no duplicated pipeline.
